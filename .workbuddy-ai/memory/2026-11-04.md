# 2026-11-04 — Fix "Failed to fetch" on client login

## Root cause
- Client login (`handleLogin`, role === 'client') was hard-wired to **Supabase Auth**
  (`client.auth.signInWithPassword`) with **no fallback**; it `return`ed inside the catch.
- The project's Supabase host `evdwvklmrgyovzthaffv.supabase.co` is **unreachable**
  (verified: supabase.com loads fine, but the project host returns `fetch failed` —
  almost certainly paused/deleted). So every client login threw a bare
  `TypeError: Failed to fetch`, surfaced raw in the toast.
- The demo credentials advertised in the auth modal (`client@kgc.ph / password`)
  live in the **local** server store (`DEMO_USERS` in server.js), not necessarily in
  Supabase Auth — so they could never work while Supabase was the only path.

## Changes

### index.html
- Added local-account fallback helpers after `getSupabaseClient()`:
  `isNetworkAuthError`, `isLocalClientSession`, `loginAgainstLocalStore`,
  `registerAgainstLocalStore`, `setLocalClientUser`, `finishClientLogin`,
  `describeClientAuthError`.
- `handleLogin` (client branch): try Supabase → on any failure fall back to
  `POST /api/auth/login` (role client) → `setLocalClientUser()` + `finishClientLogin()`.
  Only if both fail show a human-readable toast (network vs credential specific).
- `setLocalClientUser` stores a **synthetic** user object with `__local: true` in
  `portalState.supabaseAuthUser` so `isSupabaseClient` / dashboard / header menu keep working.
- `handleRegister` (client branch): on network failure falls back to
  `POST /api/auth/register`, then signs in locally.
- `logout`: skips Supabase `signOut()` for local sessions, and no longer hard-blocks
  when Supabase is unreachable (previously trapped the user signed in forever).

### server.js
- `persistBooking`, `persistBookingUpdate`, `persistUser`, `persistUserUpdate` now
  **try Supabase first and fall back to the JSON store** on error. Previously reads had
  a JSON fallback but writes returned the Supabase call directly → 500 while Supabase
  was down (broke booking submission and registration).

## Notes / gotchas
- Local client sessions are **not persisted** across refresh — `loadState()` deliberately
  refuses to restore client sessions from localStorage (Supabase session is the source
  of truth). Acceptable; user re-logs in.
- `findUserByCredentials` always checks `DEMO_USERS` after the registered store, so
  `client@kgc.ph / password` works via the API even when `data/users.json` is non-empty.
- Writes now may split data between Supabase and local JSON while Supabase is down.
  Reconcile when the Supabase project is restored.
- **This session the Bash tool was broken** (`PortableGit/usr/bin/bash.exe` not found),
  so no `node --check` / browser verification was possible. Changes reviewed statically.
