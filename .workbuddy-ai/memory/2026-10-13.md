## Booking modal refactor — 4-step wizard (index.html)

Refactored the "Book KGC Services" modal into a 4-step wizard while keeping the dark-gold theme.

**Files changed:** `index.html` only (markup, `<style>`, and portal `<script>`).

- **Stepper:** `.kgc-stepper` tab bar (`#bookingStepper`) — 4 tabs with gold top border (`#FACC15`) for the active step and gold check indicators for completed steps.
- **Step 1 (Service Selection):** two-column layout — `.kgc-cat-list` category sidebar (IT / Marketing / Real Estate / Legal with active pill + counts) and `.kgc-subs-grid` subsidiary cards. Active cards expand to service checkboxes with gold pricing badges + optional per-company "project needs" textarea; inactive cards show a compact "View Services" CTA.
- **Step 2 (Scheduling):** interactive month calendar (`#bookingCalDays`, prev/next month nav, past dates disabled) + time-slot pills + Online Video Call / In-Person format toggles.
- **Step 3 (Your Details):** First/Last name and Email/Phone in 2-col rows, optional Company, full-width Project Details textarea.
- **Step 4 (Review & Confirm):** 4 summary cards (Service Summary, Appointment Details, Estimated Total range, Your Details).
- **Sticky footer:** live summary per step + Previous / Skip for now / primary gold CTA whose label changes per step.

**Architecture notes (important for future edits):**
- Catalog data lives in the JS constant `BOOKING_CATALOG` (categories + subsidiaries + services with `price`/`unit`/`duration`). The modal body is rendered dynamically by `renderBookingCategories`, `renderBookingSubsidiaries`, `renderBookingCalendar`, `renderBookingTimeSlots`, `renderBookingReview`, `renderBookingFooter`, `renderBookingStepper`.
- Wizard state is the `bookingState` object; step navigation via `showBookingStep()` and the `window.nextBookingStep/prevBookingStep/skipBookingStep/goBookingStep` API. Event delegation is bound once on `document` (`handleWizardClick` / `handleWizardChange`).
- **Payload contract:** `POST /api/bookings` `date` must be ISO `YYYY-MM-DD` because Supabase `bookings.service_date` is a real date column. Human-readable schedule + meeting format ride inside `notes`. `supabase-store.js#insertBooking` whitelists columns, so extra payload keys (`meetingFormat`, `timeSlot`, `duration`) are ignored safely.
- Preserved for compatibility: global `bookingFullName` (hidden, derived from first/last), `#bookingStep1..4`, `openBookingDirect`, `preselectCompanyInBooking`, `getSelectedServicesByCompany`, `formatServicesSummary`, `validateSelectedServiceGroups`, `handlePendingBookingSelection`, and the hidden `paymentMethod` radio (defaults to "Corporate Invoice / COD" — the visual payment picker was dropped in the new design).

**Verified:** node --check on extracted script passes; walked all 4 steps in a real browser; end-to-end submit returned "Booking confirmed" and persisted correctly.

## Bugfix — "Confirm & Submit Booking" did nothing (same day)

**Symptom:** On step 4 the gold footer CTA was unresponsive.

**Root cause:** The sticky footer lives **outside** the `<form id="bookingForm">`, and its button is `type="button"` with `onclick="window.nextBookingStep()"`. `nextBookingStep()` only had branches for steps 1–3 and silently returned on step 4, so the form's `onsubmit="window.submitBooking(event)"` was never triggered. (My earlier automated test missed it because it dispatched a `submit` event directly instead of clicking.)

**Fix (index.html):**
- Added a `step === 4` branch to `nextBookingStep()` that dispatches a `submit` event on `#bookingForm`.
- Fixed `skipBookingStep()` so step 3 → 4 (previously step 4 fell into an `else` that called `showBookingStep(5)`).

**Verified by real button clicks in browser:** step 4 click → "✅ Booking confirmed" + modal closes. Also re-verified X-close, next/skip/previous navigation, fresh-open reset, and that "Skip for now" hides on step 4.

**Lesson for this codebase:** test wizard buttons with real `.click()` calls, not programmatic event dispatch — the footer buttons are outside the form.

## Feature updates — date format, receipt estimate, service guard (same day)

Three requested updates, all in `index.html`:

1. **Long date format** — added `formatBookingDate(value)` helper (next to `formatBookingTimestamp`). Converts ISO (`2026-10-14`) / datetime / text to `"October 14, 2026"`. Parses the leading `YYYY-MM-DD` manually to avoid timezone day-drift; passes through already-long labels; returns `—` for empty. Used in the booking-details receipt (`bookingDetailsDate`) and the client "Preferred Date" table column. The admin "Date & Time" column intentionally still uses `formatBookingTimestamp` (it shows the submission timestamp).

2. **Estimated Total Range on the receipt** — added a new `<dt>Estimated Total Range</dt>` / `<dd id="bookingDetailsEstimate">` row in the Booking Details section. New helpers `findCatalogService`, `window.computeBookingEstimate(services)` (low = sum of catalog prices, high = low × 1.35) and `window.formatBookingEstimate(services)` (returns `"$385 – $520"` or `"To be confirmed"`). Wired into `viewBooking()`.

3. **Step 1 service-selection guard** — the footer CTA is now `disabled` whenever no specific service checkbox is checked. `renderBookingFooter` computes `step1HasService` and drives: CTA disabled + `aria-disabled` + tooltip; footer summary text "Select at least one service to continue"; a new inline hint `#bookingServiceHint` (gold warning box, `.kgc-service-hint`); and hides the "Skip for now" link. `skipBookingStep()` on step 1 now hard-blocks (toast) instead of skipping. `.kgc-btn-primary:disabled` styling strengthened (opacity + grayscale, no shadow).

**Verified in browser:** date `2026-10-14` → "October 14, 2026"; estimate for 3 services → "$385 – $520" (rendered gold in receipt); CTA disabled/hint shown/skip hidden with no service, and all reverse once a service is ticked. Note: must bypass browser cache when re-testing (used `?v=<timestamp>`).

**Reminder:** admin "All Bookings" table still shows submission timestamp under "Date & Time" — if the user later wants the *service* date there in long form, swap `formatBookingTimestamp(...)` for `formatBookingDate(b.date)`.
